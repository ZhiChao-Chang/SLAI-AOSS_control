# ADS 大批量传输

用户指定 ads-cli，或需要大目录/增量同步时阅读。默认 SDK 路线更便于不暴露凭据；两者都是 AOSS 的客户端，不是 AOSS 服务本身。

先执行 `ads-cli --version`、`ads-cli --help`。官方文档目前列出 v1.11.0，并说明旧版本有同步更新问题；未来以官方页面为准。本技能不附带厂商二进制。

## 安装

从 [官方 ADS 文档](https://www.sensecore.cn/help/docs/cloud-foundation/storage/ads/) 选择匹配 OS/架构的工具包。不要把 Linux 二进制发给 Windows/macOS。可在 Linux/WSL 用户目录解压、赋予可执行权限，用绝对路径执行；不要盲目将压缩包全部展开到系统目录。官方未给可信校验和时，不编造“官方哈希验证”。下载后记录本地 SHA-256 和版本以便复现。

## 地址与方向

语法为 `ads-cli [global options] cp|sync SRC DST`。

概念示例（不是可直接复制含真实密钥的命令）：

```text
上传：LOCAL_DIR/  -> s3://AK:SK@BUCKET.ENDPOINT/PREFIX/
下载：s3://AK:SK@BUCKET.ENDPOINT/PREFIX/ -> LOCAL_DIR/
```

公网使用 `--https`，证书校验保持开启；不要照旧教程启用明文或 insecure。endpoint、桶和前缀必须来自当前用户。

注意 **ads-cli 的已核对文档将 AK/SK 放在 URI 中**，这会暴露到进程参数，也可能进入日志和命令历史。不要声称“环境变量拼出命令就没有泄露风险”。未找到本版本可验证的安全凭据通道时，优先 SDK 或官方推荐的 rclone，使用其本地私有配置；必须走 ADS 时向用户说明这项实际限制，不能代写真实含密钥命令到聊天/共享脚本。特殊字符还需要 URI 转义，不应手工猜测编码。

## cp 与 sync

- cp 是全量复制；sync 用于增量。按实际工具版本核对判断条件，不将相同大小、时间戳视为内容相同的数学证明。
- 先确认源/目的方向及目录层级，使用 `--dryrun` 预览。但 dryrun 可能仍会访问网络、列举对象和产生请求，不是离线校验。
- 不自动加 `--delete-src` 或 `--delete-dst`；它们可能删除已有数据。增量传输不要求镜像删除。
- 共享计算/网络下从低并发开始，按用户预算调整。确认现有 AFS 挂载后才能把路径当作 AFS 使用；本 skill 不新建或启动服务器。
- 给出实际传输/跳过/失败数量和字节数；CLI exit 0 不代表每个文件已独立做哈希比对。

当前机器使用同学自己的授权与存储桶，绝不复用教程里任何人的样例账户、AK/SK、IP、桶或远程启动命令。
